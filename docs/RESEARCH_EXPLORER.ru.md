# Исследовательский notebook и dashboard

Просматривайте завершённый замороженный эксперимент GLD/SLV через [исследовательский notebook](../notebooks/research.ipynb) или локальный Streamlit dashboard. Оба используют общие функции анализа и показывают записанную модель и результаты выбранного bundle. Они не обучают модели, не скачивают данные и не меняют параметры стратегии.

## Открыть notebook

После `make setup` выполните:

```sh
make run-research-notebook
```

Notebook показывает покрытие и пропуски, распределения и корреляции на train после purge, параметры и оценки моделей на validation, equity/drawdown и ошибки holdout по тикерам. Выводы вычисляются из выбранного bundle. `workflow.ipynb` сохраняет отдельную роль запуска всей цепочки.

По умолчанию выбирается последний завершённый bundle из `artifacts/`. Для защиты или сравнения укажите точный эксперимент:

```sh
CAPSTONE_RESEARCH_RUN=artifacts/full-cot-model-comparison-20261121 make run-research-notebook
```

Задайте переменную до запуска kernel или измените выбор bundle в setup-ячейке. При отсутствии bundle выводится ошибка с инструкцией; синтетические результаты не подставляются.

Выполнение и экспорт HTML без изменения notebook в Git:

```sh
CAPSTONE_RESEARCH_RUN=artifacts/full-cot-model-comparison-20261121 \
uv run --locked --no-sync jupyter nbconvert --execute --to html \
  --output-dir artifacts/research-explorer notebooks/research.ipynb
```

Для локального kernel требуется разрешение на localhost-порты. Выполненные копии notebook, HTML и изображения храните в игнорируемой `artifacts/`. В Git хранится notebook с исходными ячейками и очищенными outputs.

## Запустить dashboard

Один раз установите дополнительные зависимости из lockfile; основному CLI они не требуются:

```sh
make setup-dashboard
CAPSTONE_RESEARCH_RUN=artifacts/full-cot-model-comparison-20261121 make streamlit
```

Откройте локально `http://127.0.0.1:8501`. Остановка — Ctrl+C. Другой порт задаётся через `STREAMLIT_SERVER_PORT`, например `STREAMLIT_SERVER_PORT=8502 make dashboard`. Команда Make отключает сбор статистики использования браузера. Облачный deployment, авторизация и публичный listener не настраиваются.

`make dashboard` остаётся синонимом. В обоих каталогах есть Streamlit и Plotly; Just принимает bundle, порт или путь HTML:

```sh
make plotly
just streamlit artifacts/full-cot-model-comparison-20261121 8502
just plotly artifacts/full-cot-model-comparison-20261121 artifacts/research-explorer/comparison.html
```

`make plotly` создаёт `artifacts/research-explorer/plotly.html`. Откройте файл в браузере: Plotly JavaScript включён в HTML, интернет и сервер не нужны. Выбор через `CAPSTONE_RESEARCH_RUN` и проверки целостности совпадают с dashboard. Экспортируйте в отдельную папку вне замороженного bundle.

| Вкладка | Содержание |
|---|---|
| Data | Покрытие сигналов, пропуски признаков, сохранённые сигналы и дата последних обучающих меток модели |
| Models | Сравнение моделей только на validation, размеры хронологических разбиений и корреляции на train после purge |
| Portfolio | Интерактивные Plotly-кривые доходности и drawdown, benchmark, издержки и метрики полного портфеля |
| Errors | Ошибки holdout по тикерам, прогноз против факта и десять максимальных абсолютных ошибок |

Выбор тикера влияет только на анализ ошибок. Портфель сохраняет исходную вселенную ETF. Управления порогами и гиперпараметрами нет: отображается завершённый выбор. Reload повторно проверяет хеши результатов и не обновляет рыночные источники. Сохранённые сигналы относятся к исторической дате и не являются текущими торговыми рекомендациями.

## Целостность и интерпретация

Принимается завершённый bundle со статусом `reproduced`, пройденными ограничениями покрытия, численными результатами в `run-1/` и `inputs/effective-config.json`. Проверяются хеши всех заявленных численных outputs и effective-config, обязательные колонки и совпадение выбранной на validation модели со сводкой. Отсутствующие или изменённые файлы, заблокированный прогон и старый bundle без сравнения кандидатов вызывают явную ошибку. Просмотрщик не перепроверяет историю провайдеров и все исходные inputs: для этого используйте frozen replay исследовательского runner.

MAE/RMSE — ошибки доходности за пять сессий; доли отображаются в процентах. Доходность учитывает заданные издержки. Drawdown включает начальные торговые издержки; пик equity ограничен снизу исходным капиталом. Корреляции используют только train с метками, чей exit строго раньше validation. Анализ ошибок holdout является описательным; дальнейший подбор на этом же holdout недопустим.

Сохраняются ограничения времён доступности, ретроспективных корректировок цен, перекрывающихся меток и фиксированной вселенной ETF. Происхождение и допущения эксперимента описаны в [отчёте полного прогона](FULL_RUN.ru.md). Локальный просмотр сохранённых результатов не подтверждает live-мониторинг или начисление баллов проверяющим.

## Проверка

После установки dashboard-зависимостей:

```sh
uv run --locked --no-sync python -m pytest -q tests/unit/test_reporting.py tests/unit/test_plotly_report.py tests/integration/test_dashboard.py
```

Тесты используют явно вымышленные результаты. Проверяются чтение без изменений, ошибки целостности, корреляции только на train, независимо рассчитанные drawdown/ошибки и фильтрация тикера без изменения портфеля. Интеграционные тесты пропускаются, если дополнительные пакеты не установлены.

## Следующие приоритеты

Отдельный [адаптер Dagster](ORCHESTRATION.ru.md) теперь добавляет ручной запуск и просмотр assets/истории поверх существующего frozen runner. Расписание остаётся отдельной задачей. Evidence.dev остаётся альтернативой публикации. dlt отложен до определения конкретных incremental source/destination, cursor, ключа дедупликации и правил обработки исторических исправлений. Dashboard extra эти платформы не устанавливает.
