# Справка по командам

Makefile — точка входа для обычной локальной работы. Он использует `uv` и по умолчанию помещает окружение и кэш проекта в `.run/venv` и `.run/uv-cache`. Сначала установите [uv](https://docs.astral.sh/uv/) и Python версии 3.11 или новее, затем один раз выполните `make setup`, чтобы установить зависимости разработки из lock-файла. Запускайте команды из корня проекта. Для установки нужен доступ к package index, если зависимости ещё не кэшированы.

```sh
make help
make setup
make download       # использует проверенный кэш; загружает отсутствующее/устаревшее
make download-refresh # принудительно загружает все источники
make features       # строит аналитическую таблицу по локальным снимкам
make run            # офлайн-процесс исследования; нужны загруженные снимки
make run-notebook   # запускает Jupyter для notebooks/workflow.ipynb
make demo-synthetic # генерирует синтетические входы и визуальный HTML-отчёт
make test-demo-synthetic # проверяет офлайн human-demo
make test
make test-unit
make test-integration
make test-smoke
make test-source-smoke # проверка сети для настроенных источников; данные не сохраняются
make e2e-origin     # опционально; нужна CAPSTONE_E2E_ORIGIN
make e2e-real       # опционально; нужна CAPSTONE_E2E_CONFIG
make hooks
make install-hooks
make periodic-install  # необязательное расписание macOS; подробности в инструкции
make usage          # экспериментальная сводка локальных метаданных Codex
```

`make download` обращается к внешним поставщикам только для отсутствующих, недействительных, неполных или устаревших файлов. Кэш источника используется повторно, только если прошли проверки контрольной суммы, происхождения/тикера, схемы, уникальных упорядоченных дат, завершённых свечей, конечных цен и настроенного покрытия. Исторические архивы CFTC повторно используются после проверки суммы и разбора; архив текущего года обновляется после `download_cache_ttl_hours` (по умолчанию 24 часа в `config/settings.yml`). `make download-refresh` или `uv run capstone download --force` пропускает проверки кэша. Лог загрузки показывает решение по каждому источнику, поставщика/тикер, покрытие, размер, SHA-256 и итоговые количества загруженных, пропущенных и неудачных источников. Ошибочные ответы отклоняются до замены предыдущего снимка. Данные и результаты остаются в игнорируемых Git каталогах `data/` и `artifacts/`. E2E-тесты включаются явно; переменные окружения описаны в [инструкции запуска](RUNBOOK.ru.md). Сводка `usage` не является полным журналом сессий или отчётом о расходах.

Если история актива у поставщика начинается позже начальной даты проекта, `history_start` в `config/config.yml` задаёт самую раннюю ожидаемую дату покрытия кэша. Это граница фактически возвращённых данных, а не утверждение о дате листинга актива. После загрузки проверяйте сводки источников и sidecar-файлы: успешная команда или попадание в кэш с `0 downloaded` сами по себе не доказывают пригодность целевого ряда или доступность COT на момент публикации. Текущие проверенные диапазоны и воспроизводимый эксперимент записаны в [отчёте полного запуска](FULL_RUN.ru.md).

`make test-source-smoke` — ограниченная необязательная проверка перед загрузкой: она проверяет свежие ответы всех активных настроенных рыночных поставщиков (Yahoo Finance или Binance Spot), считывает только ZIP-сигнатуру каждого годового архива CFTC за настроенный период и проверяет страницы доказательств публикации из манифеста COT. Для каждого запроса установлен тайм-аут 8 секунд; ответы Yahoo ограничены 64 КиБ, чтение архивов CFTC — четырьмя байтами. Снимки не сохраняются. Успех подтверждает текущую доступность адресов и базовый формат ответа; он не проверяет содержимое архивов полностью, полноту данных, лицензию, время публикации COT или пригодность для исследования. При ошибке не запускайте полную загрузку. Обычные `make test` и `make test-smoke` пропускают сетевые проверки.

Офлайн-загрузка источников идемпотентна для неизменённых снимков с действительными контрольными суммами и той же конфигурации: повторные вызовы возвращают те же строки без сетевых запросов и записи файлов. Дубликаты дат отклоняются. Загрузчик по умолчанию учитывает кэш; принудительное обновление задаётся явно.

Синтетическое демо генерирует детерминированные фиктивные ряды рынка и COT, после чего запускает настоящий код построения признаков, выбора модели и симуляции. Внешние источники не вызываются, а метрики не являются исследовательскими результатами. После `make demo-synthetic` откройте `artifacts/synthetic-demo/index.html`; подробности — в [описании human-demo](SYNTHETIC_DEMO.ru.md).

В Justfile находятся вспомогательные, многошаговые и агентские операции. Для них установите [just](https://just.systems/):

```sh
just --list
just doctor
just lock-check
just compile
just verify-fast
just verify
just prompt-check <lock-slug> <session-id>
just prompt-take <lock-slug> <session-id> "<reason>"
just prompt-release <lock-slug> <session-id>
just take-next-prompt <session-id>
```

`just verify` проверяет инструменты, lock-файл в офлайн-режиме, компиляцию и полный набор тестов. `just verify-fast` запускает компиляцию и unit-, integration- и smoke-тесты. Операции сессий используют локальные advisory-блокировки объектов; срок их действия автоматически не истекает. Перед работой проверьте владельца и снимайте только собственную блокировку. Команды `make doctor`, `make verify`, `make verify-fast` и `make agents` являются делегатами Just и требуют установленного Just.

`make hooks` запускает проверки репозитория через `prek`: Lychee проверяет ссылки Markdown, включая внешние URL; Ruff выполняет lint Python-кода приложения и скриптов; локальный проверяющий скрипт офлайн проверяет пути файлов и якоря заголовков; `make verify-fast` запускает компиляцию и unit-, integration- и smoke-тесты. Также выполняются проверки пробелов, конфликтных маркеров, YAML/JSON/TOML и приватных ключей. Для внешних URL Lychee нужен доступ к сети; обычный hook проверяет выбранные `prek` Markdown-файлы, а `make hooks` и CI с `--all-files` проверяют все такие файлы. Локальная проверка путей сканирует все Markdown-файлы репозитория и работает офлайн. Быстрый набор тестов запускается, когда `prek` выбирает Python-файлы, и в CI при режиме `--all-files`. Перед запуском тех же hooks в CI устанавливаются закреплённые dev-зависимости.

Например, переменные окружения можно переопределить так:

```sh
UV_PROJECT_ENVIRONMENT=.run/venv UV_CACHE_DIR=.run/uv-cache make test
UV_PROJECT_ENVIRONMENT=.run/venv UV_CACHE_DIR=.run/uv-cache just verify
```

Настройка источников и офлайн-повтор описаны в [инструкции запуска](RUNBOOK.ru.md), границы этапов — в [архитектуре](ARCHITECTURE.ru.md).

Интервал можно изменить командой `make periodic-install PERIODIC_INTERVAL_MINUTES=60`. Цели `periodic-uninstall` и `periodic-run` удаляют расписание или запускают один цикл. См. [инструкцию по периодическому коммиту и push](PERIODIC_COMMIT_PUSH.ru.md) с описанием ограничений и поведения.
