# ADR-0002: Сохранение исследовательских снимков и локальных временных настроек

- **Статус:** Принято для текущего локального процесса; внешнее резервное хранилище этим ADR не реализовано.
- **Дата:** 2026-11-21
- **Область:** Хранение данных, применение Git LFS и размещение `.run/idempotence-settings.yml`.

## Контекст

Повторная загрузка не гарантирует восстановление исходных данных эксперимента. В проекте уже возникали ошибки DNS и ответы HTTP 403. Исторические рыночные цены могут пересматриваться или корректироваться задним числом. CFTC предоставляет [годовые исторические архивы](https://www.cftc.gov/MarketReports/CommitmentsofTraders/HistoricalCompressed/index.htm), но наличие архива не гарантирует побайтовое восстановление прежней загрузки и не подтверждает время публикации отчётов.

При проверке 2026-11-21 каталог `data/` занимал около 21 МБ. [Правила проекта](../../.ai/RULES.md) и [план реализации](../../.ai/IMPLEMENTATION_PLAN.md) исключают скачанные данные из Git. Локальная реализация исследовательского запуска в `src/capstone/research.py` уже копирует исходные снимки, свидетельства публикаций, конфигурацию, исходный код и определения зависимостей в каталог эксперимента, записывает хеши входов и поддерживает сравнение детерминированных результатов. При подготовке ADR эта реализация ещё не была закоммичена и не входит в данный коммит документации. Её наличие не доказывает успешный полный эксперимент на реальных данных или создание внешней резервной копии.

Игнорируемый файл `.run/idempotence-settings.yml` в основном повторяет [общие настройки](../../config/settings.yml), задавая `output_dir: .run/idempotence-output`. При проверке ссылки на это временное имя в коде и документации проекта не найдены; в файле также отсутствовал общий параметр `download_cache_ttl_hours`. Его перенос создаст ещё одну поддерживаемую конфигурацию, которая может расходиться с основной.

## Решение

1. Оставить `data/` игнорируемым локальным кэшем. Сейчас не подключать Git LFS ко всему каталогу.
2. Сохранять неизменяемые снимки входов для значимых экспериментов. Включать исходные данные и файлы метаданных, SHA-256, сведения об источниках и загрузке, итоговую конфигурацию, манифест публикаций COT и версию кода/зависимостей для повторного запуска. При обновлении рабочего кэша сохранять исходные байты эксперимента.
3. Хранить комплекты экспериментов в отдельном резервном хранилище; небольшой манифест снимка и инструкции восстановления хранить в Git. Хеши идентифицируют и проверяют данные, но не восстанавливают утраченные байты. Место хранения, политика удержания и процедура восстановления ещё требуют реализации и проверки.
4. До передачи снимков проверять права на распространение данных. [Проект yfinance](https://github.com/ranaroussi/yfinance) предупреждает о personal use для Yahoo Finance API; права публичного распространения здесь не установлены. Этот ADR не разрешает публикацию скачанных рыночных данных.
5. Оставить `.run/idempotence-settings.yml` локальным временным файлом. Общие исследовательские и runtime-настройки хранить в `config/settings.yml`, результаты проверок — в `.run/`.
6. Если проверка идемпотентности станет поддерживаемым документированным сценарием, добавить именованный профиль в `config/`. Предпочитать переопределение только отличающихся параметров полному копированию общих настроек. Необходимую поддержку профилей/переопределений реализовать и проверить до описания её как доступной.

## Рассмотренные альтернативы

- **Всегда скачивать заново:** недостаточно для точного повторения, поскольку доступность источников и исторические значения могут меняться.
- **Хранить весь `data/` через Git LFS:** отложено. [Git LFS](https://git-lfs.com/) хранит указатели в Git, а содержимое файлов — на отдельном сервере. Он позволяет версионировать снимки вместе с кодом, но добавляет зависимости хранения и получения файлов и не решает вопрос прав распространения. Текущие правила проекта также исключают эти файлы из Git.
- **Просто перенести временную копию настроек в `config/`:** отложено, поскольку это закрепит дублирование без поддерживаемого сценария и ссылок на него.

## Последствия и условия пересмотра

Локальный процесс остаётся простым, а точная воспроизводимость зависит от сохранения и резервного копирования фактических входов эксперимента. Локальные замороженные комплекты сами по себе не защищают от потери компьютера или диска. Производные данные и генерируемые результаты остаются воспроизводимыми артефактами вне Git, если отдельное решение не установит необходимость их хранения.

Вернуться к LFS, когда участникам понадобятся конкретные версии данных с разрешённым распространением вместе с checkout и будут обоснованы требования к хранению и доступу. Для внедрения потребуется явно пересмотреть действующую политику хранения данных в Git и определить состав снимков вместо включения каждого файла кэша. Пересмотреть размещение конфигурации при появлении стабильной команды проверки идемпотентности и документированного контракта профиля.

Этот ADR фиксирует только политику: файлы в `data/` и `.run/` не перемещались, настройка LFS не добавлялась, внешняя резервная копия не создавалась.
