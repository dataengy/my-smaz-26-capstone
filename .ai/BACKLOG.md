# Project backlog

This is the canonical local backlog for the capstone. The [bug register](BUGS.md) records discovered defects and their fix evidence; prioritize open implementation work here. The immediate parallel work and handoff prompts are in [next steps](NEXT_STEPS.md) and [parallel session prompts](PARALLEL_SESSION_PROMPTS.md); current evidence is in [status](STATUS.md). When configured, GitHub Issues and the linked Projects v2 board visualize and queue work; keep acceptance criteria and evidence here, and link each tracker item to its backlog/bug entry. Requirements are in the [capstone specification](../openspec/specs/capstone/spec.md), and ownership and verification history are in the [implementation plan](IMPLEMENTATION_PLAN.md). A task is complete only when its acceptance evidence is recorded.

Status: **open** = actionable; **blocked** = requires an unavailable input or access; **deferred** = optional until its trigger is met. P0 gates the core research, P1 supports defensible acceptance, and P2 is optional.
