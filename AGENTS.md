# Project agent instructions

This repository is a standalone Stock Market Analytics Zoomcamp capstone. Preserve existing user work and do not copy code, scripts, dependency files, or data from the reference course checkout. Use it only as reference material. Do not add it as a submodule as part of this task.

- Read [the implementation plan](.ai/IMPLEMENTATION_PLAN.md), [project rules](.ai/RULES.md), and the relevant [role profiles](.ai/roles/ROLES.md) before substantive work. Consult [project memory](.ai/memory/PROJECT_MEMORY.md) and [requirements](openspec/specs/capstone/spec.md) for decisions and evidence.
- Keep documentation describing the implemented project for people and agents in `docs/`; keep agentic plans, backlog, rules, session management, prompts and memory in `.ai/`. Link rather than duplicate their content.
- English is the primary project documentation language. Provide Russian mirrors for the main human-facing documents using `.ru.` in their filenames and reciprocal language-switch links; update translations alongside the source.
- Do not fabricate data, experiments, tests, costs, deployments, or outcomes. Distinguish verified evidence from assumptions and unfinished work.
- Preserve point-in-time availability, use time-based evaluation, and keep the test period out of model and strategy selection. Document execution timing, costs, and data limitations.
- Never commit downloaded market data, secrets, environments, or large generated artifacts. Do not expose raw private session logs or unrelated project data.
- The orchestrator assigns each worker specific files or responsibilities, integrates changes, and updates the shared plan. Workers must not revert others' work. Before editing, inspect parallel-session ownership and acquire advisory object locks for exact files or shared contracts; object locks are the default. Release only your own lock after handoff, and never clear a lock based only on age. See `.ai/.codex/skills/parallel-session-coordination/SKILL.md` and global `agent-session-lock`. If critical work cannot wait, isolate it in a separate Git worktree when Git is available; do not run concurrent writers in one worktree. This workspace currently has no Git repository, so worktree isolation is unavailable. QA independently checks integrated results.
- Relevant Superpowers and Ponytail skills should be read and used where appropriate; direct user and system instructions take precedence. Project skill drafts are under `.ai/.codex/skills/`; automatic discovery is not established. Read a draft directly when relevant.
- Keep common human commands in `Makefile`; put reusable, multi-step, parameterized and agent/session operations in `Justfile`. Read `.ai/.codex/skills/build-command-interface/SKILL.md` before editing either command catalog and validate both surfaces.
- OpenSpec is the selected spec-driven framework. The requirements files are readable without its CLI; do not claim CLI validation or installation without evidence. Avoid extra infrastructure until the local core workflow works.
